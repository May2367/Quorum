# Linearizability Tests

KV linearizability checking is implemented in `internal/linearizability` and exercised by server tests plus the Docker netem workflow.

The checker records operation histories with start/end times and call/return values, then validates them with both the local KV checker and Porcupine. Current coverage includes multi-node leader-failover histories, partition histories, replayable seeded partition histories, and Docker `tc netem` histories generated by `cmd/kv-history-check`.

The core rule remains: no linearizability claim should be made unless the recorded history passes the checker for its seed.
